## Тросмерни меч са РоцксДБ/фјалл

<б ид="1"> Користите исти управљачки програм за фазу и исто кодирање кључа (8-бајтни биг-ендиан индекс на крају,
Редослед речника је у складу са редоследом индекса) Тест фкв, РоцксДБ, фјалл: РоцксДБ је прошао
<б ид="1"> Преведена дељена библиотека се учитава са длопен-ом (исти Ц
АБИ, Руст буилд се не повезује са РоцксДБ), фјалл користи <б ид="1"> директно. Сваки од три мотора отвара библиотеку.
Напредите на исту библиотеку по редоследу фаза: масовно оптерећење креира податке, а затим лен / очитавање тачке / читање опсега /
Сва брисања утичу на исте податке.

```bash
cargo build --release -p fkv_compare
басх сцриптс/перф/буилд_роцксдб_ффи.сх # Прескочи трећу колону ако нема РоцксДБ
./target/release/fkv_compare \
  --rows 25000000 --bulk-rows 25000000 --cache-bytes 268435456 \
  --readers 1,4,8,16,32 --workdir /tmp/fkv-compare \
  --rocksdb-lib target/perf/librocksdb_bench_ffi.so \
  --json /tmp/fkv-compare.json
```

Бројеви за матрицу почетне странице могу доћи само из једног следљивог покретања:

```bash

  --json /tmp/fkv-compare.json --perf-js web/src/conf/perf.js \
  --мацхине "..." --соурце "ЦИ рун <б ид="1">"
```

### калибра

- **Однос података/кеш меморије**: 25.000.000 редова × 116 Б ≈ 2766 МиБ података, 256 МиБ кеш меморије по машини,
  ≈ 11:1, у складу са РоцксДБ-овим званичним прегледом података од 97 ГиБ/кеш меморије од 6 ГиБ (≈ 16:1).
- **Иста количина кеш меморије**: фкв кеш страница (индекс/подаци исти скуп), РоцксДБ блок кеш
  (<б ид="1">, величина блока 4 КиБ), фјалл-ов сопствени блок кеш
  Сви буџети су подешени на исти број бајтова.
- **Калибар постојаности (колона за поређење користи подразумевану конфигурацију РоцксДБ, без поравнања)**: фкв 1×страница са подацима + по групи
  1×манифест <б ид="1"> (изоморфно СинцДата + АппендМанифест Ц++ ЕлокСторе,
  Ниједна нема прекидач за искључивање); колона РоцксДБ користи **подразумевану конфигурацију** (ВАЛ укључен, <б ид="1">,
  Нема секвенцијалне фсинц), фјалл такође користи подразумевани (<б ид="1">). Стога фаза писања (једнократно уписивање /
  Разлика између групних уписа) је **разлика у снази постојаности**, а не разлика у примени, која мора бити наведена на страници заједно са бројем.
  Ако желите да анализирате "ко је бржи под истом јачином синхронизације", додајте <б ид="1"> (отворите РоцксДБ са синц=труе,
  фјалл користи СинцАлл), ова опција се не користи за екстерно објављене матрице.
- **Два фкв драјвера**: <б ид="1"> (подразумевано, директно повезан са једним <б ид="2"> у оквиру процеса, и
  РоцксДБ / фјалл су такође позиви библиотеке) и <б ид="1"> (режим примене: процес
  <б ид="1"> фрагментне нити, захтеви се рутирају помоћу кључа, усклађени са јавним читањем и писањем Ц++ ЕлокСторе-а
  интерфејс). Сваки захтев последњег треба да прође кроз ред + буђење унакрсних нити, изворни (мацОС, датотека ИО пролази кроз скуп нити)
  Време читања је око 20 µс/време, што је за ред величине спорије од директне везе у процесу; много јефтиније на Линук/ио_уринг, али
  Још увек скок. Матрица странице користи калибар продавнице, а калибар времена извршавања се користи за „формулар за примену у односу на Ц++
  Поређење „Јавног интерфејса“ (фкв рунтиме сингле-тхреад читање је око 50 копс/с, Ц++ ЕлокСторе ФФИ сингле-тхреад
  крхотина око 21 копс/с).
- **Калибар истовремене читања**: број бочне нити фкв = <б ид="1">, подразумевано
  Горња граница је 4 (усклађено са вЦПУ машине за процену), **не** "једна нит по читачу" - прекорачени ниво само повећава ред чекања;
  Кеш меморија по нити = 256 МиБ / број нити (укупна количина је фиксна, није уситњена читачима) и користи се
  <б ид="1"> Задржите <б ид="2"> (подразумевано 16) захтеве у покрету. РоцксДБ страна је
  <б ид="1"> Сваки <б ид="2"> чита истовремено; једнонитна петља на фјалл страни (занемарујући опрему за читање,
  Само као референтна колона). <б ид="1"> може поново да се дегенерише у „испреплетених Н асинхроних ланаца у једном времену извршавања“.
  То је дубина цевовода, а не истовременост, и није упоредива са свим моторима.
- **лен()**: Ниједан од три механизма нема интерфејсе за бројање О(1). Ова линија је стопа бројања пуне табеле, а не О(1) тражење.
