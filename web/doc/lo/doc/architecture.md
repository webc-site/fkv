# ສະຖາປັດຕະຍະກໍາ

## ເວລາແລ່ນ

ແຕ່ລະ shard ມີກະທູ້ OS ສະເພາະ ແລະ compio runtime. ການຮ້ອງຂໍເຂົ້າໄປໃນແຖວ ingress,
ການເຂົ້າຮຽນໂດຍເຄື່ອງຂອງລັດ shard, ສໍາເລັດໂດຍຜ່ານໃບຮັບເງິນ oneshot.

## ການເກັບຮັກສາ

ເຄື່ອງຈັກໃຊ້ copy-on-write B+tree. ຫນ້າຂໍ້ມູນ, ຫນ້າດັດສະນີ, overflow chain ແລະ
manifest ແມ່ນ serialized ເປັນ segment files. ສາຂາຖືກລະບຸໂດຍ `(branch, term)` ແລະຖືກຈັດຂຶ້ນໂດຍແຕ່ລະຄົນ
manifest ແລະພາບຖ່າຍແຜນທີ່.

## IO

`fkv_io` ກຳນົດລັກສະນະ IO asynchronous. `fkv_io_compio` ປະຕິບັດກັບ compio + io_uring,
`fkv_io_mem` / `fkv_io_sim` ໃຫ້​ຄວາມ​ຊົງ​ຈໍາ​ແລະ​ຄວາມ​ຜິດ​ພາດ​ດ້ານ​ຫຼັງ​ການ​ສັກ​ຢາ​, `fkv_object_s3` ໃຫ້
ເບື້ອງຫຼັງວັດຖຸ S3.

## ຄວາມຄົງທົນ

Manifest ບັນທຶກໜ້າຮາກ, ຮາກ TTL, ສາຂາ metadata ແລະການສ້າງແຜນທີ່. ເມື່ອເປີດຄືນໃໝ່
ທຳອິດຫຼິ້ນ manifest ຄືນໃໝ່, ຈາກນັ້ນສ້າງຕົວແຜນທີ່ໜ້າຄືນໃໝ່, ແລະຫຼັງຈາກນັ້ນເລີ່ມໃຫ້ບໍລິການຄຳຮ້ອງຂໍ.
