# කාර්ය සාධනය

`fkv_bench` ස්ථාවර යතුරු ඉඩක් මත බර ලිවීම, කියවීම සහ ස්කෑන් කිරීම පරීක්ෂා කරන්න.

```bash
cargo run --release -p fkv_bench -- \
  --workload write-read --rows 20000 --batch-size 100
```

දර්ශකවලට ප්‍රතිදානය, එක් එක් අදියරේදී ප්‍රමාදය සහ උපරිම RSS ඇතුළත් වේ. කාර්ය ප්‍රවාහ මුදා හැරීම x86_64 /
aarch64 සඳහා `fkv_bench` ද්විමය.

## RocksDB/fjall සමඟ තුන්-මාර්ග ගැලපීම

`crate/perf/fkv_compare` එකම අදියර ධාවකය සහ එකම යතුරු කේතනය භාවිතා කරන්න (අවසානයේ 8-byte big-endian subscript,
ශබ්ද කෝෂය අනුපිළිවෙල අනුපිළිවෙලට අනුකූල වේ) ටෙස්ට් fkv, RocksDB, fjall: RocksDB සමත් විය
`crate/perf/fkv_compare/cpp/rocksdb_ffi.cpp` සම්පාදනය කරන ලද හවුල් පුස්තකාලය dlopen (එම C) සමඟ පටවා ඇත
ABI, Rust build RocksDB වෙත සම්බන්ධ නොවේ), fjall සෘජුවම `fjall 3` භාවිතා කරයි. එන්ජින් තුනෙන් එක් එක් පුස්තකාලයක් විවෘත කරයි.
අදියර අනුපිළිවෙලින් එකම පුස්තකාලයේ ඉදිරියට යන්න: තොග බර දත්ත නිර්මාණය කරයි, පසුව len / point කියවීම / පරාසය කියවීම /
මකාදැමීම් සියල්ලම එකම දත්ත වලට බලපායි.

```bash
cargo build --release -p fkv_compare
bash scripts/perf/build_rocksdb_ffi.sh # RocksDB නොමැති නම් තුන්වන තීරුව මඟ හරින්න
./target/release/fkv_compare \
  --rows 25000000 --bulk-rows 25000000 --cache-bytes 268435456 \
  --readers 1,4,8,16,32 --workdir /tmp/fkv-compare \
  --rocksdb-lib target/perf/librocksdb_bench_ffi.so \
  --json /tmp/fkv-compare.json
```

මුල් පිටු න්‍යාසය සඳහා සංඛ්‍යා පැමිණිය හැක්කේ එක් සොයා ගත හැකි ධාවනයකින් පමණි:

```bash
python3 scripts/perf/fkv_compare_to_js.py \
  --json /tmp/fkv-compare.json --perf-js web/src/conf/perf.js \
  --machine "..." --source "CI ධාවනය <id>"
```

GitHub Actions' `perf.yml` මෙය හරියටම සිදු කරයි (`librocksdb-dev`, ක්‍රමලේඛ ඇඩප්ටර ස්ථාපනය කරන්න, ධාවනය කරන්න
25M පේළි න්‍යාසය, කෞතුක වස්තුව උඩුගත කරන්න, සහ `backfill=true` විට පිටුව කෙලින්ම ආපසු පුරවන්න).

### calibre

- **දත්ත/හැඹිලි අනුපාතය**: පේළි 25,000,000 × 116 B ≈ 2766 MiB දත්ත, එන්ජිමකට හැඹිලි 256 MiB,
  ≈ 11:1, 97 GiB දත්ත/6 GiB හැඹිලි (≈ 16:1) පිළිබඳ RocksDB හි නිල සමාලෝචනය සමඟ සමපාත විය.
- **එකම හැඹිලි ප්‍රමාණය**: fkv හි පිටු හැඹිලිය (දර්ශකය/දත්ත එකම සංචිතය), RocksDB හි වාරණ හැඹිලිය
  (`cache_index_and_filter_blocks=true`, වාරණ ප්‍රමාණය 4 KiB), fjall ගේම බ්ලොක් හැඹිලිය
  අයවැය සියල්ලම එකම බයිට් ගණනකට සකසා ඇත.
- ** Persistence caliber (සැසඳීමේ තීරුව RocksDB පෙරනිමි වින්‍යාසය, පෙළගැස්වීමකින් තොරව භාවිතා කරයි)**: fkv 1×data page + per batch
  1× ප්‍රකාශනය `fdatasync` (සමමුහුර්ත දත්ත වලට සමස්ථානික + C++ EloqStore හි AppendManifest,
  අක්‍රිය ස්විචයක් ද නැත); RocksDB තීරුව **පෙරනිමි වින්‍යාසය** භාවිතා කරයි (WAL on, `WriteOptions.sync=false`,
  අනුක්‍රමික fsync නැත), fjall පෙරනිමිය ද භාවිතා කරයි (`PersistMode::Buffer`). එබැවින් ලිවීමේ අදියර (තනි ලිවීම /
  කණ්ඩායම් ලිවීම් අතර වෙනස) යනු ** නොනැසී පවතින ප්‍රබල වෙනස** මිස ක්‍රියාත්මක කිරීමේ වෙනස නොවේ, එය අංකය සමඟ පිටුවේ සඳහන් කළ යුතුය.
  ඔබට "එකම සමමුහුර්ත කිරීමේ ශක්තිය යටතේ වේගවත් කවුද" යන්න විශ්ලේෂණය කිරීමට අවශ්‍ය නම්, `--align-fsync` එක් කරන්න (Sync=true සමඟ RocksDB විවෘත කරන්න,
  fjall SyncAll භාවිතා කරයි), මෙම විකල්පය බාහිරව ප්‍රකාශිත න්‍යාස සඳහා භාවිතා නොවේ.
- **fkv ධාවක දෙකක්**: `--fkv-driver store` (පෙරනිමිය, ක්‍රියාවලිය තුළ තනි `Store` වෙත සෘජුවම සම්බන්ධ කර ඇත, සහ
  RocksDB / fjall ද පුස්තකාල ඇමතුම් වේ) සහ `--fkv-driver runtime` ( යෙදවීමේ මාදිලිය: ක්‍රියාවලියකි
  `--fkv-shards` ෂාර්ඩ් නූල්, ඉල්ලීම් යතුර මගින් යොමු කරනු ලැබේ, C++ EloqStore හි පොදු කියවීම සහ ලිවීම සමඟ සමපාත වේ
  අතුරු මුහුණත). දෙවැන්නාගේ සෑම ඉල්ලීමක්ම පෝලිම + හරස් නූල් අවදි කිරීම, ස්වදේශික (macOS, ගොනු IO නූල් සංචිතය හරහා යයි) හරහා යා යුතුය.
  කියවීමේ කාලය 20 µs/time පමණ වේ, එය ක්‍රියාවලියේ සෘජු සම්බන්ධතාවයට වඩා විශාලත්වයේ අනුපිළිවෙලක් මන්දගාමී වේ; Linux/io_uring මත බෙහෙවින් ලාභදායී, නමුත්
  තවමත් පැනීමකි. පිටු න්‍යාසය ගබඩා ක්‍රමාංකනය භාවිතා කරන අතර ධාවන කාල ක්‍රමාංකය " යෙදවීමේ පෝරමය එදිරිව C++ සඳහා භාවිතා වේ
  "පොදු අතුරුමුහුණත" සංසන්දනය (fkv ධාවන කාලය තනි නූල් කියවීම 50 kops/s, C++ EloqStore FFI තනි නූල්
  shard 21 kops/s පමණ).
- ** සමගාමී ක්‍රමාංකය කියවන්න**: fkv පැති නූල් අංකය = `min(readers, --read-max-concurrency)`, පෙරනිමිය
  ඉහළ සීමාව 4 (ඇගයුම් යන්ත්‍රය vCPU සමඟ පෙළගස්වා ඇත), ** නොවේ ** "කියවන්නෙකුට එක් නූල්" - ඉක්මවා ගිය මට්ටම පෝලිම පමණක් වැඩි කරයි;
  නූලකට හැඹිලිය = 256 MiB / නූල් ගණන (මුළු මුදල සවි කර ඇත, පාඨකයන් සමඟ ඉරා දමා නැත) සහ භාවිතා වේ
  `FuturesUnordered` `--read-window` (පෙරනිමි 16) ඉල්ලීම් පියාසර කරන්න. RocksDB පැත්ත තමයි
  `readers` සෑම `std::thread` එකක්ම එකවර කියවයි; fjall පැත්තේ තනි නූල් පුඩුවක් (පාඨක ආම්පන්න නොසලකා හැරීම,
