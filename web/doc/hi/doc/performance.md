# प्रदर्शन

`fkv_bench` एक निश्चित कुंजी स्थान पर परीक्षण लिखें, पढ़ें और स्कैन लोड करें।

```bash
cargo run --release -p fkv_bench -- \
  --workload write-read --rows 20000 --batch-size 100
```

संकेतकों में थ्रूपुट, प्रत्येक चरण में विलंबता और चरम आरएसएस शामिल हैं। रिलीज़ वर्कफ़्लो रिलीज़ x86_64 /
`fkv_bench` aarch64 के लिए बाइनरी।

## RocksDB/fjall के साथ तीन-तरफा मैचअप

`crate/perf/fkv_compare` समान स्टेज ड्राइवर और समान कुंजी एन्कोडिंग का उपयोग करें (अंत में 8-बाइट बिग-एंडियन सबस्क्रिप्ट,
शब्दकोश क्रम सबस्क्रिप्ट क्रम के अनुरूप है) परीक्षण fkv, RocksDB, fjall: RocksDB उत्तीर्ण
`crate/perf/fkv_compare/cpp/rocksdb_ffi.cpp` संकलित साझा लाइब्रेरी को dlopen (वही C.) से लोड किया गया है
ABI, रस्ट बिल्ड RocksDB से लिंक नहीं है), fjall सीधे `fjall 3` का उपयोग करता है। तीनों इंजनों में से प्रत्येक एक पुस्तकालय खोलता है।
चरणों के क्रम में एक ही लाइब्रेरी पर आगे बढ़ें: बल्क लोड डेटा बनाता है, और फिर लेन / पॉइंट रीडिंग / रेंज रीडिंग /
सभी विलोपन समान डेटा को प्रभावित करते हैं।

```bash
cargo build --release -p fkv_compare
bash स्क्रिप्ट/perf/build_rocksdb_ffi.sh # यदि कोई RocksDB नहीं है तो तीसरा कॉलम छोड़ें
./target/release/fkv_compare \
  --rows 25000000 --bulk-rows 25000000 --cache-bytes 268435456 \
  --readers 1,4,8,16,32 --workdir /tmp/fkv-compare \
  --rocksdb-lib target/perf/librocksdb_bench_ffi.so \
  --json /tmp/fkv-compare.json
```

होम मैट्रिक्स के नंबर केवल एक ट्रेस करने योग्य रन से आ सकते हैं:

```bash
python3 scripts/perf/fkv_compare_to_js.py \
  --json /tmp/fkv-compare.json --perf-js web/src/conf/perf.js \
  --मशीन "..." --स्रोत "सीआई रन <बी आईडी='1">"
```

GitHub Actions' `perf.yml` बिल्कुल यही करता है (`librocksdb-dev` इंस्टॉल करें, प्रोग्राम एडेप्टर चलाएं,
25M पंक्ति मैट्रिक्स, आर्टिफैक्ट अपलोड करें, और `backfill=true`) होने पर सीधे पृष्ठ को बैकफ़िल करें।

### कैलिबर

- **डेटा/कैश अनुपात**: 25,000,000 पंक्तियाँ × 116 बी ≈ 2766 एमआईबी डेटा, 256 एमआईबी कैश प्रति इंजन,
  ≈ 11:1, RocksDB की 97 GiB डेटा/6 GiB कैश (≈ 16:1) की आधिकारिक समीक्षा के साथ संरेखित।
- **कैश की समान मात्रा**: एफकेवी का पेज कैश (इंडेक्स/डेटा समान पूल), रॉक्सडीबी का ब्लॉक कैश
  (`cache_index_and_filter_blocks=true`, ब्लॉक आकार 4 KiB), fjall का अपना ब्लॉक कैश
  सभी बजट बाइट्स की समान संख्या पर सेट हैं।
- **दृढ़ता कैलिबर (तुलना कॉलम बिना संरेखण के RocksDB डिफ़ॉल्ट कॉन्फ़िगरेशन का उपयोग करता है)**: fkv 1×डेटा पृष्ठ + प्रति बैच
  1×मैनिफ़ेस्ट `fdatasync` (आइसोमोर्फिक टू सिंकडेटा + C++ EloqStore का एपेंडमैनिफ़ेस्ट,
  न ही कोई ऑफ स्विच है); RocksDB कॉलम **डिफ़ॉल्ट कॉन्फ़िगरेशन** का उपयोग करता है (WAL on, `WriteOptions.sync=false`,
  कोई अनुक्रमिक fsync नहीं), fjall डिफ़ॉल्ट (`PersistMode::Buffer`) का भी उपयोग करता है। इसलिए लेखन चरण (एकल लेखन/
  बैच राइट्स के बीच अंतर **दृढ़ता शक्ति अंतर** है, न कि कार्यान्वयन अंतर, जिसे संख्या के साथ पृष्ठ पर बताया जाना चाहिए।
  यदि आप विश्लेषण करना चाहते हैं कि "समान सिंक्रोनाइज़ेशन शक्ति के तहत कौन तेज़ है", तो `--align-fsync` जोड़ें (रॉक्सडीबी को सिंक=ट्रू के साथ खोलें,
  fjall SyncAll का उपयोग करता है), इस विकल्प का उपयोग बाहरी रूप से प्रकाशित मैट्रिक्स के लिए नहीं किया जाता है।
- **दो एफकेवी ड्राइवर**: `--fkv-driver store` (डिफ़ॉल्ट, सीधे प्रक्रिया के भीतर एकल `Store` से जुड़ा होता है, और
  RocksDB / fjall भी लाइब्रेरी कॉल हैं) और `--fkv-driver runtime` (परिनियोजन मोड: एक प्रक्रिया
  `--fkv-shards` शार्ड थ्रेड, अनुरोधों को कुंजी द्वारा रूट किया जाता है, C++ EloqStore के सार्वजनिक पढ़ने और लिखने के साथ संरेखित किया जाता है
  इंटरफ़ेस)। बाद के प्रत्येक अनुरोध को कतार + क्रॉस-थ्रेड वेक-अप, मूल (macOS, फ़ाइल IO थ्रेड पूल के माध्यम से जाता है) से गुजरना होगा
  पढ़ने का समय लगभग 20 µs/समय है, जो इन-प्रोसेस प्रत्यक्ष कनेक्शन की तुलना में धीमी गति का क्रम है; Linux/io_uring पर बहुत सस्ता, लेकिन
  अभी भी एक छलांग है. पेज मैट्रिक्स स्टोर कैलिबर का उपयोग करता है, और रनटाइम कैलिबर का उपयोग "परिनियोजन फॉर्म बनाम सी++" के लिए किया जाता है
  "सार्वजनिक इंटरफ़ेस" की तुलना (fkv रनटाइम सिंगल-थ्रेड रीडिंग लगभग 50 kops/s है, C++ EloqStore FFI सिंगल-थ्रेड
  लगभग 21 kops/s) का टुकड़ा।
- **संवर्ती कैलिबर पढ़ें**: एफकेवी साइड थ्रेड नंबर = <बी आईडी = "1">, डिफ़ॉल्ट
  ऊपरी सीमा 4 है (मूल्यांकन मशीन वीसीपीयू के साथ संरेखित), **नहीं** "प्रति पाठक एक थ्रेड" - बढ़ा हुआ स्तर केवल कतार को बढ़ाता है;
  कैश प्रति थ्रेड = 256 एमआईबी / थ्रेड्स की संख्या (कुल राशि निश्चित है, पाठकों के साथ कटा हुआ नहीं), और उपयोग किया गया
  `FuturesUnordered` `--read-window` (डिफ़ॉल्ट 16) अनुरोधों को चालू रखें। RocksDB पक्ष है
  `readers` प्रत्येक `std::thread` एक साथ पढ़ता है; एफजेएलएल साइड पर सिंगल-थ्रेडेड लूप (रीडर्स गियर को नजरअंदाज करते हुए,
  केवल संदर्भ स्तंभ के रूप में)। `--no-fkv-read-threads` वापस "एकल रनटाइम पर इंटरलीव्ड एन एसिंक्रोनस चेन" में परिवर्तित हो सकता है।
  यह पाइपलाइन की गहराई है, संगामिति नहीं, और सभी इंजनों में तुलनीय नहीं है।
- **len()**: तीनों इंजनों में से किसी में भी O(1) काउंटिंग इंटरफ़ेस नहीं है। यह पंक्ति पूर्ण तालिका गणना दर है, O(1) लुकअप नहीं।
