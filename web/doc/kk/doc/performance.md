# Өнімділік

`fkv_bench` Бекітілген кілт кеңістігіндегі жүктемелерді жазуды, оқуды және сканерлеуді тексеру.

```bash
cargo run --release -p fkv_bench -- \
  --workload write-read --rows 20000 --batch-size 100
```

Көрсеткіштерге өткізу қабілеттілігі, әр кезеңдегі кідіріс және ең жоғары RSS кіреді. x86_64 шығарылымының жұмыс үрдісін шығарыңыз /
aarch64 үшін `fkv_bench` екілік.

## RocksDB/fjall көмегімен үш жақты сәйкестік

`crate/perf/fkv_compare` Бірдей кезең драйверін және бірдей кілт кодтауын пайдаланыңыз (соңында 8 байт үлкен-эндиан жазылуы,
Сөздік реті жазылу ретімен сәйкес келеді) Test fkv, RocksDB, fjall: RocksDB өтті
`crate/perf/fkv_compare/cpp/rocksdb_ffi.cpp` Құрастырылған ортақ кітапхана dlopen арқылы жүктеледі (сол C
ABI, Rust құрастыру RocksDB-ге сілтеме жасамайды), fjall тікелей `fjall 3` пайдаланады. Үш қозғалтқыштың әрқайсысы кітапхана ашады.
Бір кітапханада кезеңдердің реті бойынша алға жылжу: жаппай жүктеме деректерді жасайды, содан кейін len / нүктелік оқу / диапазонды оқу /
Жоюлардың барлығы бірдей деректерге әсер етеді.

```bash
cargo build --release -p fkv_compare
bash scripts/perf/build_rocksdb_ffi.sh # RocksDB болмаса, үшінші бағанды ​​өткізіп жіберіңіз
./target/release/fkv_compare \
  --rows 25000000 --bulk-rows 25000000 --cache-bytes 268435456 \
  --readers 1,4,8,16,32 --workdir /tmp/fkv-compare \
  --rocksdb-lib target/perf/librocksdb_bench_ffi.so \
  --json /tmp/fkv-compare.json
```

Басты бет матрицасына арналған сандар тек бір қадағаланатын жұмыстан келуі мүмкін:

```bash
python3 scripts/perf/fkv_compare_to_js.py \
  --json /tmp/fkv-compare.json --perf-js web/src/conf/perf.js \
  --machine "..." --source "CI іске қосу <id>"
```

GitHub Actions' `perf.yml` дәл осылай жасайды (`librocksdb-dev` орнату, бағдарлама адаптерлері, іске қосу
25M жол матрицасы, артефакті жүктеп салыңыз және `backfill=true` болғанда бетті тікелей толтырыңыз.

### калибрлі

- **Деректер/кэш арақатынасы**: 25 000 000 жол × 116 Б ≈ 2766 МБ деректер, бір қозғалтқыш үшін 256 МБ кэш,
  ≈ 11:1, RocksDB-тің 97 ГБ деректер/6 ГБ кэш (≈ 16:1) туралы ресми шолуына сәйкес.
- **Кэштің бірдей көлемі**: fkv бетінің кэші (индекс/деректер бірдей пул), RocksDB блок кэші
  (`cache_index_and_filter_blocks=true`, блок өлшемі 4 КБ), fjall-тың жеке блок кэші
  Бюджеттердің барлығы бірдей байт санына орнатылады.
- **Төзімділік калибрі (салыстыру бағаны RocksDB әдепкі конфигурациясын теңестірмей пайдаланады)**: fkv 1×деректер беті + әр топтама
  1×манифест `fdatasync` (SyncData үшін изоморфты + C++ EloqStore қолданбасының AppendManifest,
  Ешқайсысында да өшіру қосқышы жоқ); RocksDB бағаны **әдепкі конфигурацияны** пайдаланады (WAL қосулы, `WriteOptions.sync=false`,
  Кезекті fsync жоқ), fjall әдепкі параметрді де пайдаланады (`PersistMode::Buffer`). Сондықтан жазу кезеңі (бір рет жазу /
  Пакеттік жазбалар арасындағы айырмашылық) нөмірмен бірге бетте көрсетілуі тиіс орындалу айырмашылығы емес, **тұрақтылық күшінің айырмашылығы** болып табылады.
  Егер сіз «бірдей синхрондау күшімен кім жылдамырақ екенін» талдағыңыз келсе, `--align-fsync` қосыңыз (RocksDB файлын sync=true арқылы ашыңыз,
  fjall SyncAll пайдаланады), бұл опция сырттан жарияланған матрицалар үшін пайдаланылмайды.
- **Екі fkv драйвері**: `--fkv-driver store` (әдепкі, процесс барысында бір `Store` тікелей қосылған және
  RocksDB / fjall да кітапхана шақырулары болып табылады) және `--fkv-driver runtime` (орналастыру режимі: процесс
  `--fkv-shards` үзінді ағындары, сұраулар C++ EloqStore жалпы оқуына және жазылуына сәйкес келетін кілт арқылы бағытталады
  интерфейс). Соңғысының әрбір сұрауы кезектен өтуі керек + кросс-ағынды ояту, жергілікті (macOS, IO файлы жіп пулынан өтеді)
  Оқу уақыты шамамен 20 мкс/уақыт, бұл процесстегі тікелей қосылуға қарағанда баяуырақ; Linux/io_uring жүйесінде әлдеқайда арзан, бірақ
  Әлі де секіру. Бет матрицасы дүкен калибрін пайдаланады, ал орындау уақыты калибрі "орналастыру пішіні және C++" үшін пайдаланылады
  «Қоғамдық интерфейсті» салыстыру (fkv орындалу уақытының бір ағынды оқуы шамамен 50 копс/с, C++ EloqStore FFI бір ағынды
  сынық шамамен 21 копс/с).
- **Параметрлік калибрді оқу**: fkv бүйірлік жіп нөмірі = `min(readers, --read-max-concurrency)`, әдепкі
  Жоғарғы шегі 4 (бағалау машинасы vCPU-мен тураланған), ** емес** «әр оқырманға бір ағын» - асып кеткен деңгей тек кезекті арттырады;
  Әр ағындағы кэш = 256 МБ / ағындар саны (жалпы сома бекітілген, оқырмандармен ұсақталмаған) және пайдаланылған
  `FuturesUnordered` `--read-window` (әдепкі 16) сұрауларды жылдам сақтаңыз. RocksDB жағы болып табылады
  `readers` Әрбір `std::thread` бір уақытта оқиды; fjall жағындағы бір ағынды цикл (оқушыларды елемей,
  Тек анықтамалық баған ретінде). `--no-fkv-read-threads` "бір орындалу уақытында араласқан N асинхронды тізбекке" қайта тозуы мүмкін.
  Бұл құбырдың тереңдігі, параллельдік емес және қозғалтқыштар арасында салыстыруға келмейді.
- **len()**: үш қозғалтқыштың ешқайсысында O(1) санау интерфейстері жоқ. Бұл жол O(1) іздеу емес, толық кестені санау жылдамдығы болып табылады.
